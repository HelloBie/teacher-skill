# 阶段五：结业考试

在整个课程大纲的全部内容实际讲授完成后加载。本阶段以真实课纲、已授内容和学习目标为依据，准备综合考核供学习者检验能力；由学习者决定何时参加。用户明确要求调整、延期或跳过时尊重其决定并如实记录。

## 进入条件与命题依据

1. 读取最新课程计划、各课教学状态、讲义/整课总结、已发生的问答及学习记录，核对每个大纲模块是否实际讲授。计划、课件、练习模板或单课结束不代表课程全部学完。
2. 全部课程已讲授时，设计涵盖各主要模块与关键能力的考核。过往课后题未补充或尚未通过，不自动阻止参加，也不能计为已掌握。对跳过或未讲的内容先按学习者意愿补教；如果用户明确要求提前测试，说明覆盖与缺失范围，标记为阶段性测试，不冒称完整课程结业考试。
3. 按课纲的目标、知识覆盖、实际应用和评价依据制订命题蓝图：列主要模块或能力、对应课次、考核题号/任务、题型、分值或评价标准。考已讲内容及其合理综合应用，不引入未讲且完成所必需的新知识；跨课综合题应清晰给出业务背景和必要数据。
4. 依据学科调整题型和难度：概念题、判断/选择、简答、案例分析、技能操作、实践项目或代码可合理组合，不强制编程题或考试时长。题量适中，分值、权重、通过标准或能力评价标准明确；如题目有多种可行答案，说明以哪些依据评价，而非只有唯一措辞。若学习者已有要求，按其要求调整。

## 文件与试卷规范

遵循现有课程目录；若无相应约定，在课程根目录按需创建：

```text
exams/
  README.md          # 考核范围、试卷版本、文件入口与实际状态
  exam_01.md         # 题目、分值或评价标准、答题要求及答案位置
  ...                # 特定学科需要的操作资料、起步代码或答题文件
```

- `README.md` 记录课程范围、命题蓝图（模块/能力 → 题号 → 分值或评价项）、各文件链接、答题方式、是否允许查阅资料（未约定可明确允许）、提交方式、评分方式及实际状态。说明这是一份自测，成绩的可靠性受题目覆盖、答题条件及实际可验证证据限制。
- `exam_01.md` 写清题目编号、题型、完整条件、必要数据、答题位置及每题分值或标准；选择题标明单选或多选。题型和语言适合课程，避免题意不充分。按学科需要在同目录提供答题文件、案例、素材或代码起步文件；需要运行的内容给命令、环境要求及可观察验收目标，不能让公开样例直接泄露整题答案。
- 发卷时公开范围、规则、分值和评价维度，但不预填答案，也不向学习者提前展示具体参考答案或逐题解析；不使用未公开的答案来训练学生。不要把公开本地文件当成安全或保密机制。如果需要计算机辅助验证，仅准备不直接暴露答案的条件和测试方式；最终反馈依据实际提交。
- 校验题目覆盖与课纲映射、总分/权重、题目条件、文件链接和必要可运行材料。避免遗漏核心模块或超出实际授课范围；若无法验证实操部分，明确标记限制，不宣称已验证。

## 发卷、讲评与结业状态

1. 将试卷及答题入口交给学习者，写明如何完成与提交，在 `docs/学习记录.md` 和考试入口记录“已发卷、待作答”、范围和链接；出卷不表示已答题或通过。
2. 学习者提交或请求讲评时，读取实际试卷、提交的答案、已有批注及评分标准。保留原答案、解释和代码；逐题追加带日期和轮次的老师批注，写清结论、得分或评价、证据、原因及改进建议。代码用不改变行为的注释；实际操作以可观察证据为准。未提交题明确标记，不猜答案；题意有问题时承认并合理调整评分。
3. 按公布的规则汇总各模块结果及总分或能力评价，解释优势、待提升项与证据；区分“已提交待讲评”“已讲评未通过/待完善”“已通过”。只依据实际可核查结果判断，不把授课、生成试卷、部分正确或用户口头称完成自动算作通过；自测结果不宣称是官方证书或独立认证。
4. 可在 `exams/讲评_01.md` 另附总评、各模块结果、复习建议与必要解析；若使用独立讲评文件，逐题批注仍须就近追加至答案下方，保留所有轮次。未提交题暂不公开解析。更新考试入口、学习记录和课程入口，包含考试版本、状态、结果和文件链接。
5. 学习者要求重考时使用新的试卷或答卷版本并保留前次题目、答案与讲评，不覆盖或改写历史；命题及评分仍基于最新实际大纲。补学或重考时间由学习者决定。
