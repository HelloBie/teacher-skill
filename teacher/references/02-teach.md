# 阶段二：教学与课后练习

讲授某部分、准备该课材料或创建课后练习时读取。参照已有课程的命名和目录；以下为新建课程的默认结构。只讲已准备的内容，按实际学科调整例子和题型。

## 执行步骤

1. 读取现有课程计划、学习记录、当前课入口、已讲内容与作答，确定课次和接下来未讲的部分；学生指定顺序优先。
2. 按四个问题在聊天中讲解，展示例子，再带领跟练；按下方规范保存实质讲义。
3. 在本课创建题目和答题位置及入口，检查条件、示例和链接；概念题与实践题按学科选取。
4. 更新本课入口、练习入口及学习记录，区分已讲授、已发题、未提交及下一步；交付讲义和练习链接。
5. 若本课所有计划部分刚刚讲完，随后加载课后总结阶段；如果仅完成一个部分，不创建整课总结。

## 本课入口 `lessons/lesson_XX/README.md`

开始该课时创建，随实际进度维护：课次总数、编号、标题；本课目标与已讲/未讲部分；当前练习和讲评的实际状态；讲义、练习入口、问答和整课总结（存在时）的链接。它是导航，不以空链接替代内容；分段讲完不写成整课或能力已完成。

## 分段讲义 `lessons/lesson_XX/lesson_YY.md`

每次实际授课后保存该部分；使用不会覆盖现有文件的编号。每份必须包含实质讲解，而不是只有标题、TODO 或外链：

```markdown
# 共 <总数> 节课，第 <课次> 节（<编号>）｜<课题>
本次内容：第 <部分> 部分——<主题>

## 1. 这是什么
定义、作用、必要背景、术语解释与能力边界。

## 2. 哪些情况会用到
符合学科和学习目标的具体场景、使用原因和不适用条件。

## 3. 如何使用
前置知识、清晰的步骤或完整例子、必要解释、预期结果、易错点；
按实际需要提供环境、命令、数据、失败及资源处理说明。

## 4. 类似方案与取舍
比较能实现相同目标的实际方法，说明差异、适用条件和成本；
不存在直接替代时明确说明，不生造方案。

## 带领跟练
基于已讲内容的具体操作或思考步骤，以及预期现象。

## 课后练习
链接本部分真实练习及答题方式。
```

标题和组织可适配学科，但四个教学问题、示例及跟练需有实际内容。聊天也要实际讲授，不能只链接讲义。涉及版本、专业事实或高风险领域时按需核对权威资料。

## 练习入口 `lessons/lesson_XX/exercises/EXERCISES.md`

每次布置或讲评更新：按部分列出题号、目标/题型、题目与答题文件链接、逐题实际状态。可在入口直接放题目；若使用分段题目文件，入口必须链接对应文件。学生答案、脚本、草稿及题目都归该课 `exercises/`；演示和讲义放该课目录或项目约定位置。不能覆盖已作答内容或重复题号。

## 分段题目 `lessons/lesson_XX/exercises/part_YY.md`

每次授课后创建实际题目，默认约三道，依学习目标和反馈调整。每题包含：题号与题型（选择题注明单选/多选）、完整条件和任务、答题方式及位置、验收标准。概念题提供“我的答案/理由”等空白；支持在聊天回答。参考结构：

```markdown
## 题 <编号>：<题型>——<主题>
<条件、问题或选项；不得依赖未教知识>

我的答案：
我的理由：

验收：<判断答案达到目标的标准>
```

代码或其他实际操作题还需根据任务提供初始数据/材料、步骤、运行或操作方式、可观察的预期结果及验收边界。代码题提供该课目录下的起步文件、项目根目录运行命令、清晰变量/术语解释、待完成位置；验证示例、命令和占位行为，不将占位输出当成通过。非代码学科采用适合的材料，不强制代码或命令。未讲过的概念不得直接作为必做题；未批改时不预填答案或解析。

## 演示与自检

示例或素材有必要时放在该课目录或既有项目指定位置，并由讲义链接。交付前核对讲义、入口、题目、起步文件及链接是否存在；题目条件是否充分；示例及可运行模板是否符合说明；学习记录与练习入口是否只写已讲、已发题或待作答等真实状态。

## `lessons/lesson_XX/课堂问答.md`

本课出现真实知识提问且已回答时创建或追加。每条包含编号或主题、日期、学生实际原问题、回答要点和相关讲义/示例链接；后续澄清继续追加并保留原文。参考格式：

```markdown
## Q<编号>：<主题>（<日期>）
**学生原问题：** <实际提问原文>
**回答要点：** <老师实际解释的关键内容>
**相关材料：** <存在的讲义或示例链接>
```

不存在提问时不编造，也不为凑篇幅自问自答。回答未完成时标注待解，不虚称已解答。


学生课堂提问时按上方格式记录原问题和实际回答，并在学习记录中链接问答和如实更新当前阶段；不因回答问题推断已经讲完或通过。
