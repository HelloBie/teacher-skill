# Stage 2: Teaching and exercises

Load this stage when teaching or answering a course question. Use the learner's instructional language for explanations, examples, exercises, feedback and course materials. Preserve the existing layout and student work.

## Steps

1. Read the syllabus, progress, current lesson entry, taught parts and existing answers. Select the next untaught part unless the learner explicitly chooses another topic.
2. In the conversation, announce total lessons, lesson number and title, and part number and topic. Teach what the concept is, when and why it is used, how it works with a worked example and expected result, and comparable approaches with their tradeoffs. Explain prerequisites and terms, then demonstrate and guide a small practice.
3. Save substantive lesson notes and create actual exercises and answer spaces in this lesson's exercise folder. Validate questions, examples and links. Never test untaught prerequisite knowledge.
4. Update the lesson entry, exercise index and progress record with what was taught, assigned, submitted and what comes next; provide links. If all planned parts of this lesson were just taught, load the lesson-summary stage. Otherwise do not call the entire lesson complete.

## Lesson entry and notes

Create or update `lessons/lesson_XX/README.md`, or the existing equivalent, with lesson number, title, goals, taught and untaught parts, truthful exercise status and links to existing materials. It is navigation, not a substitute for content.

Save each taught part in a uniquely numbered file such as `lessons/lesson_XX/lesson_YY.md`. Include the lesson header and part, substantive sections for **what it is**, **when it is used**, **how to use it** with prerequisites, example, expected result and pitfalls, and **alternatives and tradeoffs**. Add guided practice with an expected observation and a link to this part's exercises. If no direct alternative exists, compare different ways to achieve the same goal. Verify unstable or high-stakes facts against appropriate authoritative sources.

## Exercise files

Create or update `lessons/lesson_XX/exercises/EXERCISES.md` with links, question numbers, objectives and actual status. Create a new uniquely numbered question/answer file, for example `part_YY.md`; do not overwrite existing responses. Match question types to the subject, often around three questions: multiple choice, true/false, short answer, scenario, analysis, performance or code. Each question must include complete conditions, answer method/space and acceptance criteria. Mark single or multiple selection for choice questions. The learner may answer conceptual questions in chat.

Practical tasks include needed starting data or materials, steps and observable acceptance criteria. Code tasks also provide a starter file, runnable command, expected output, a clearly marked unfinished area and needed terminology. Check that examples and starters behave as described; a runnable placeholder is not a pass. Do not prefill answers or publish solutions before review. Non-code subjects do not need code or commands.

## Real classroom questions

When a learner asks a real course question, answer it and append the original question, date, substantive explanation and related material links to the lesson Q&A file, for example `questions.md`. Preserve prior entries and original language; do not invent questions. Update progress and links without claiming that answering a question means the lesson is complete or passed.
