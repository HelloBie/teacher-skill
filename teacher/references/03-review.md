# 阶段三：练习讲评

用户提交答案、请求检查或复查时加载。按题目条件评价，并保留学生作答。

## 执行步骤

1. 读取当前课题目、学习者实际作答、历史批注和学习记录；区分未提交、已答和题意有问题的题。
2. 检查思路、要求及必要的边界情况，保留原答案；按下方格式逐题追加反馈。
3. 校验原文和程序行为未变，更新本课练习入口、课程入口与学习记录的逐题状态、轮次、证据及下一步；交付讲评。

## 逐题批注：写在原答案下方

依据题目条件与实际作答逐题检查；必要时用隔离数据或内存验证例子和边界，不为验证而修改学生源文件。原题、答案、解释和历史批注原样保留。Markdown 答案下追加独立区块，默认格式：

```markdown
### 老师批注（第 <轮次> 轮，<日期>）
**结论：** <通过 / 部分正确 / 需修改 / 未提交 / 题意待澄清>
**证据与原因：** <具体作答或验证结果；说明正确处和问题原因>
**提示：** <需要时给可执行的修改方向，不直接代改>
```

代码文件在学生代码和解释下方追加符合该语言的注释，包含同样的信息，不能改变程序行为。复查时继续追加新轮次，不删除旧内容。未作答应记未提交、暂不评分，不猜答案或提前公开对应解析；题意不充分时如实说明，不把合理答案判错。学生在聊天作答时，可在征得相应上下文允许的课程答题文件中如实记录原文并在下方批注，不伪造文件中原本存在的内容。

批改后核对原作答完整、程序行为未因注释改变；同步本课练习入口、课程入口和学习记录的逐题状态与证据链接。学生不想补充或修改的旧题保留记录，不反复提醒、不设为继续授课前置条件，也不凭此记为通过。
